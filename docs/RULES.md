# 정책보고서 생성기 — 작성·출력 규칙 (권위 문서)

이 문서는 구현과 보고서 생성이 반드시 따르는 규칙이다. 충돌 시 이 문서가
설계 문서의 일반 서술보다 우선한다.

---

## 1. 할루시네이션 방지 규칙
- 출처 불명 정보는 **수집 금지**.
- 모든 정보에 **출처 URL · 저자 · 발행일** 필수 기록.
- 출처의 연도를 거짓으로 표기하는 행위 **금지**.
- 모든 출처는 **직접 연결하여 내용을 확인**할 것.

출처 모델 = **하이브리드**: 사용자 제공 문서 + 명시된 URL. 생성 시 Claude Code(구독)가
각 URL을 직접 fetch해 스니펫·발행일을 대조 검증한다(웹 '검색'은 안 함, 명시 URL만 fetch).

구현 함의:
- 인용(Citation) 데이터 모델은 `text`(verbatim 스니펫)뿐 아니라
  `url` · `author` · `published_date` · `source_id`를 **필수 필드**로 가진다.
- `verify`는 (a) 스니펫이 원문에 실재하는지 + (b) URL·저자·발행일 메타데이터가
  채워져 있는지 둘 다 검사. 하나라도 미충족이면 인용 제거.
- **검증 통과 인용이 0개인 주장은 보고서에서 삭제한다**(표식을 남기지 않음).
  검증 기록(verified.json)에는 `needs_evidence`로 남겨 무엇이 왜 빠졌는지 감사 가능하게
  하되, 최종 DOCX 출력에서는 해당 문장을 렌더링하지 않는다. 주장이 모두 빠진 섹션은 생략.
- 발행연도는 원문/메타데이터에서 가져온 값만 기록. 추정·생성 금지.

## 2. DOCX 생성 규칙
- **docx-js 사용** (`npm install docx`).
- A4 크기: `width=11906, height=16838` (DXA).
- 기본 폰트: **신명조 11pt**.
- 여백: 위/아래 39, 오른쪽/왼쪽 35, 머리말 12, 꼬리말 12.
- 줄간격 180, 들여쓰기 2, 자간 0.
- 표: `WidthType.DXA`, `ShadingType.CLEAR` 사용.
- 이미지: `ImageRun`에 `type` 파라미터 필수.
- 각주: `FootnoteReferenceRun` 사용.
- `\n` 사용 금지 → 별도 `Paragraph`로 분리.
- 페이지별 각주 및 참고문헌 작성.

## 3. 논문작성 핵심 원칙 (생성되는 보고서 본문의 문체)
> 사용자 지시: 퍼플렉시티·버스티니스를 인위적으로 극대화하고 "AI가 절대 안 쓸
> 표현"을 의도적으로 박아넣는 것은 Claude Code 기본 문체가 마음에 들지 않아서이며,
> 그대로 따른다. (이 규칙은 **생성되는 보고서 본문**에 적용된다.)

### 퍼플렉시티(Perplexity) 극대화
- 예측 불가능한 단어 선택: 뻔한 표현 대신 의외의 비유, 구어체, 전문용어 혼용.
- AI가 절대 쓰지 않을 표현 의도적 사용.
- 완벽한 문법 대신 약간의 구어적 비문 허용.

### 버스티니스(Burstiness) 극대화
- 문장 길이를 극단적으로 변화 (3~5어절 ↔ 30어절 이상 복합문).
- 단락 길이도 들쭉날쭉하게 배치.
- 글머리 기호/번호 목록 남발 금지, 산문 위주.

### AI 문체 제거
- "~는 매우 중요합니다" → 경험/사례로 보여줄 것.
- "첫째, 둘째, 셋째" → 서사적 흐름으로 연결.
- "다양한/효과적인/혁신적인" → 구체적 수치/사례로 교체.
- 종결어미 최소 5종 이상 혼용 (-다, -는 거다, -더라, -ㄹ 수밖에 없다, -지 않을까 등).
- 저자의 입장을 명확히 드러내고 양비론 지양.

> 주의: 규칙 3(문체)은 보고서 본문 생성에만 적용된다. 규칙 1(출처 정확성)·2(DOCX
> 형식)와 충돌하지 않는다 — 문체를 흔들더라도 출처·수치·발행연도는 정확해야 한다.
